完整 UI 設計流程                                                                                   
                                                                                                     
  前置產出（在 feature-to-ui 之前）                                                                  
                                                                                                     
  .feature 檔（需求規格）                                                                            
         ↓ /feature-to-flow
  .flow.md（操作流程 + testid 定義）← testid 的 single source of truth

  feature-to-ui 主流程

  ui-config-pm.yaml (PM 填寫)
         ↓ Phase 0 自動同步
  ui-config.yaml (工程師版)
         ↓
  Phase 0 → 1 → 2 → 3 → 4 → 5 → 6

  三份關鍵文件的角色

  ┌────────────────┬──────────────────────────────────────────────┬──────────────────┐
  │      文件      │                     角色                     │      誰產出      │
  ├────────────────┼──────────────────────────────────────────────┼──────────────────┤
  │ *.dsl.feature  │ 需求規格的 single source of truth            │ PM / 需求分析    │
  ├────────────────┼──────────────────────────────────────────────┼──────────────────┤
  │ *.flow.md      │ testid + 操作流程的 single source of truth   │ /feature-to-flow │
  ├────────────────┼──────────────────────────────────────────────┼──────────────────┤
  │ route-map.yaml │ 路由與 feature 對照的 single source of truth │ Phase 0          │
  └────────────────┴──────────────────────────────────────────────┴──────────────────┘

  .flow.md 的使用規則

  - 若 .flow.md 存在 → 必須以它為準，testid 不能自行命名
  - 若 .flow.md 不存在 → 可依 rules.md 命名規則自行定義 testid
  - Phase 6 實作每個功能前，強制讀取對應的 .flow.md 和 _common.flow.md

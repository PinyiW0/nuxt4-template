# 診斷檢查項目

## 1. Frontmatter 檢查

| 項目 | 檢查內容 | 判定標準 |
|------|----------|----------|
| name | 命名規範 | 小寫、連字號、≤64 字元 |
| description | 用途說明 | 是否清楚說明用途與觸發時機 |
| 觸發設定 | 合理性 | 有副作用的任務是否設 `disable-model-invocation` |
| allowed-tools | 最小權限 | 是否只開放必要的工具 |
| context | 執行環境 | 複雜任務是否該用 `fork` |

### Description 評估要點

**好的 description**：
- 說明「做什麼」和「何時用」
- 包含用戶可能說的關鍵字
- 排除容易混淆的情況

```yaml
# ❌ 不好
description: 處理程式碼
```

```yaml
# ✅ 好
description: |
  格式化 TypeScript 程式碼，修正縮排與分號。
  用於整理程式碼、統一風格、或用戶說「格式化」「prettier」「lint fix」時觸發
```

## 2. 內容結構檢查

| 項目 | 檢查內容 | 判定標準 |
|------|----------|----------|
| 長度 | SKILL.md 行數 | > 500 行為 warning |
| 冗餘 | 重複內容 | 是否有相似段落 |
| 流程 | 步驟清晰度 | 是否有明確 input/output |
| 支援檔案 | 內容分離 | 詳細文檔是否該移到支援檔案 |

### 內容分離建議

```
# Before: 單一 600 行 SKILL.md

# After:
SKILL.md (< 100 行，概覽與導航)
├── reference.md (詳細說明)
├── template.md (輸出範本)
└── examples/ (使用範例)
```

---

## 3. 觸發準確度檢查

| 項目 | 檢查內容 | 判定標準 |
|------|----------|----------|
| 關鍵字 | 涵蓋度 | description 是否包含常見用法的詞彙 |
| 混淆 | 功能重疊 | 是否與其他 skill 功能相似 |
| 誤觸發 | 範圍控制 | 是否過於寬泛導致不該觸發時觸發 |

### 關鍵字評估

分析 description 中的關鍵字，對比用戶可能的說法：

| 用戶可能說 | description 是否涵蓋 |
|-----------|---------------------|
| 格式化程式碼 | ✓ |
| prettier | ✗ 缺少 |
| lint fix | ✗ 缺少 |

---

## 4. 執行效率檢查

| 項目 | 檢查內容 | 判定標準 |
|------|----------|----------|
| context | 執行環境 | 複雜獨立任務是否用 fork |
| 工具限制 | 減少選擇 | 是否用 allowed-tools 縮小範圍 |
| 並行步驟 | 效率 | 是否有可並行但寫成序列的步驟 |

### Context 選擇建議

| 情況 | 建議 |
|------|------|
| 簡單參考/指引 | `inline` |
| 需要對話歷史 | `inline` |
| 複雜多步驟任務 | `fork` |
| 探索程式碼 | `fork` + `agent: Explore` |
| 設計方案 | `fork` + `agent: Plan` |

---

## 狀態判定

| 狀態 | 定義 |
|------|------|
| `pass` | 符合最佳實踐 |
| `warning` | 可改善但不影響功能 |
| `fail` | 有明確問題需要修正 |

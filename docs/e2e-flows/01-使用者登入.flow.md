# 使用者登入 — E2E 操作流程

> 頁面：登入頁（/login）

## 元素定義

| 元素 | testid | 說明 |
|------|--------|------|
| 登入頁面 | login-page | 頁面容器 |

> 帳號欄位、密碼欄位、登入按鈕見 _common.flow.md

## 共用前置條件

- 「系統中有以下使用者：」→ 不需操作（mock 資料已預設）

## 規則：使用者以帳號密碼登入，成功後取得 JWT Token

### 情境：登入成功

前置條件：
- 「使用者 "coach1" 尚未登入」→ 不需操作（預設未登入）

操作步驟：
- 「使用者以帳號 "coach1" 密碼 "pass123" 登入」
  1. 前往登入頁 → /login
  2. 在「帳號」欄位輸入 coach1 → #login-account
  3. 在「密碼」欄位輸入 pass123 → #login-password
  4. 點擊「登入」按鈕 → #login-submit

預期結果：
- 「操作成功」→ 跳轉到 /
- 「系統回傳 Access Token（有效期 1-2 小時）」→ ⏭️ 跳過（畫面上看不到 token）
- 「系統回傳 Refresh Token（有效期 7 天）」→ ⏭️ 跳過（畫面上看不到 token）
- 「系統產生 "使用者已登入" 事件」→ ⏭️ 跳過（內部事件）

## 規則：帳號或密碼錯誤時登入失敗

### 情境：密碼錯誤

前置條件：
- 「使用者 "coach1" 尚未登入」→ 不需操作（預設未登入）

操作步驟：
- 「使用者以帳號 "coach1" 密碼 "wrongpass" 登入」
  1. 前往登入頁 → /login
  2. 在「帳號」欄位輸入 coach1 → #login-account
  3. 在「密碼」欄位輸入 wrongpass → #login-password
  4. 點擊「登入」按鈕 → #login-submit

預期結果：
- 「操作失敗」→ 顯示錯誤提示
- 「系統顯示 "帳號或密碼錯誤"」→ 文字「帳號或密碼錯誤」可見

### 情境：帳號不存在

前置條件：
- 「使用者 "unknown" 不存在」→ 不需操作（mock 資料已預設）

操作步驟：
- 「使用者以帳號 "unknown" 密碼 "pass123" 登入」
  1. 前往登入頁 → /login
  2. 在「帳號」欄位輸入 unknown → #login-account
  3. 在「密碼」欄位輸入 pass123 → #login-password
  4. 點擊「登入」按鈕 → #login-submit

預期結果：
- 「操作失敗」→ 顯示錯誤提示
- 「系統顯示 "帳號或密碼錯誤"」→ 文字「帳號或密碼錯誤」可見

## 規則：連續登入失敗 5 次後，帳號鎖定 15 分鐘

### 情境：第 5 次登入失敗後帳號被鎖定

⏭️ 整個情境跳過
原因：需要控制內部狀態（連續登入失敗次數），E2E 無法精確模擬

### 情境：鎖定期間嘗試登入

⏭️ 整個情境跳過
原因：需要控制內部狀態（帳號鎖定狀態），E2E 無法精確模擬

### 情境：鎖定期滿後可重新登入

⏭️ 整個情境跳過
原因：需要控制內部狀態（鎖定過期），E2E 無法精確模擬

## 規則：Access Token 過期後可用 Refresh Token 換取新 Token

### 情境：使用 Refresh Token 換取新 Access Token

⏭️ 整個情境跳過
原因：無對應 UI 的 API 操作（Refresh Token 換取是純 API 行為）

### 情境：Refresh Token 已過期

⏭️ 整個情境跳過
原因：無對應 UI 的 API 操作（Refresh Token 換取是純 API 行為）

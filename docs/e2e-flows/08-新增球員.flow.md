# 新增球員 — E2E 操作流程

> 頁面：球員管理（/players）

## 元素定義

| 元素 | testid | 說明 |
|------|--------|------|
| 球員頁面 | players-page | 頁面容器 |
| 球員列表 | player-list | 球員表格 |
| 新增球員按鈕 | player-create | 開啟新增彈窗 |
| 表單彈窗 | player-form-modal | 新增/編輯共用彈窗 |
| 背號欄位 | player-number | 背號輸入框 |
| 姓名欄位 | player-name | 姓名輸入框 |
| 身高欄位 | player-height | 身高輸入框 |
| 守備位置欄位 | player-position | 守備位置下拉選單 |
| 儲存按鈕 | player-save | 彈窗送出按鈕 |

## 共用前置條件

- 「系統中有以下使用者：」→ 不需操作（mock 資料已預設）
- 「系統中有以下球隊：」→ 不需操作（mock 資料已預設）
- 「球隊 "藍鷹隊" 中有以下球員：」→ 不需操作（mock 資料已預設）

## 規則：新增球員需提供背號、姓名、身高、守備位置

### 情境：成功新增球員

前置條件：
- 「教練 "coach1" 已登入」→ （共用步驟，見 _common.flow.md）

操作步驟：
- 「教練在 "藍鷹隊" 新增球員：」
  1. 前往球員管理頁 → /players
  2. 點擊「新增球員」按鈕 → #player-create
  3. 等待彈窗出現 → #player-form-modal
  4. 在「背號」欄位輸入 10 → #player-number
  5. 在「姓名」欄位輸入 李大華 → #player-name
  6. 在「身高」欄位輸入 180 → #player-height
  7. 在「守備位置」欄位選擇 捕手 → #player-position
  8. 點擊「建立」按鈕 → #player-save

預期結果：
- 「操作成功」→ 顯示成功提示「球員已新增」
- 「系統產生 "球員已新增" 事件」→ ⏭️ 跳過（內部事件）

## 規則：背號必須為 0-999 的整數

### 情境：背號超出範圍

⏭️ 整個情境跳過
原因：表單驗證，由單元測試覆蓋

### 情境：背號為負數

⏭️ 整個情境跳過
原因：表單驗證，由單元測試覆蓋

## 規則：同球隊內背號必須唯一

### 情境：新增重複背號的球員

前置條件：
- 「教練 "coach1" 已登入」→ （共用步驟，見 _common.flow.md）

操作步驟：
- 「教練在 "藍鷹隊" 新增球員背號為 1」
  1. 前往球員管理頁 → /players
  2. 點擊「新增球員」按鈕 → #player-create
  3. 等待彈窗出現 → #player-form-modal
  4. 在「背號」欄位輸入 1 → #player-number
  5. 在「姓名」欄位輸入 測試球員 → #player-name
  6. 在「身高」欄位輸入 175 → #player-height
  7. 在「守備位置」欄位選擇 投手 → #player-position
  8. 點擊「建立」按鈕 → #player-save

預期結果：
- 「操作失敗」→ 顯示錯誤提示「該背號已被使用」
- 「系統顯示 "該背號已被使用"」→ 文字「該背號已被使用」可見

### 情境：不同球隊可使用相同背號

⏭️ 整個情境跳過
原因：涉及切換球隊操作，複雜度高，由 API 層級驗證

## 規則：身高必須為 100-250 公分

### 情境：身高低於下限

⏭️ 整個情境跳過
原因：表單驗證，由單元測試覆蓋

### 情境：身高超出上限

⏭️ 整個情境跳過
原因：表單驗證，由單元測試覆蓋

## 規則：守備位置必須為固定選項之一

### 情境：使用有效的守備位置

⏭️ 整個情境跳過
原因：已包含在「成功新增球員」情境中驗證

### 情境：使用無效的守備位置

⏭️ 整個情境跳過
原因：下拉選單不會有無效選項，UI 無法觸發

## 規則：球員姓名長度為 1-50 字元

### 情境：球員姓名為空

⏭️ 整個情境跳過
原因：表單驗證，由單元測試覆蓋

## 規則：教練只能在自己的球隊中新增球員

### 情境：教練在自己的球隊新增球員

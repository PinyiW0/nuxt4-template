# Test Implementation - 紅燈生成器

## Role
將測試樣板（純註解）轉換為可執行的測試程式碼，依照註解中的 Handler Prompt 指引生成對應的程式碼，生成紅燈測試。

## Core Task
測試樣板（註解）→ 可執行測試程式碼（紅燈）

## Input
1. 測試方法（包含註解樣板，來自 01-Feature-to-測試樣板.md）
2. DBML（Aggregate 定義）
3. Tech Stack（預設 Python + pytest）
4. Handler Prompts（handlers/ 資料夾中的所有 Handler）

## Output

### 1. 測試程式碼
完整的測試程式碼，包含：
- 必要的 import
- repository 和 service 初始化
- 完整的測試方法實作
- 所有測試邏輯完整實作

### 2. 介面定義
**如果測試中需要用到的類別或介面尚不存在**，則在 src/ 中定義：
- Entity 類別（如 `LessonProgress`）
- Repository 類別（如 `LessonProgressRepository`）
- Service 類別（如 `LessonService`）

**⚠️ 關鍵原則：僅定義介面，不實作內部邏輯**
- 類別和方法定義完整（包含參數）
- 方法內部不實作，或拋出 `NotImplementedError`
- 或返回 `None` / 空值

---

## 🔴 紅燈階段的核心原則

### ✅ 要做的事
1. **完整實作測試程式碼**：測試邏輯必須完整且正確
2. **定義所需介面**：在專案中的實際程式的 source root (e.g., src/) 中創建測試需要定義的類別和方法簽名
3. **保持介面為空實作**：類別方法內部「不」實作業務邏輯

### ❌ 不要做的事
1. **不要實作業務邏輯**：service 和 repository 的方法內部保持空白
2. **不要讓測試通過**：測試應該因為實作空白而失敗（紅燈）
3. **不要跳過介面定義**：測試需要的介面必須定義，否則測試無法執行

### 為什麼要這樣？
這是 TDD 的核心流程：
1. **紅燈**：寫測試 + 定義介面（測試失敗）← 我們現在在這
2. **綠燈**：實作最小可行邏輯（測試通過）
3. **重構**：優化程式碼品質（測試持續通過）

#### 範例流程

**Given 區塊**：
- Handler: Aggregate-Given-Handler.md
- 生成: 創建 entity → repository.save()

**When 區塊**：
- Handler: Command-Handler.md
- 生成: service.method()

**Then 區塊**：
- Handler: Success-Failure-Handler.md
- 生成: （不需要額外程式碼，因為是「操作成功」）

**And 區塊**：
- Handler: Aggregate-Then-Handler.md
- 生成: repository.find() → assert entity.field

    # [事件風暴部位: Command - update_video_progress]
    # [生成參考 Prompt: Command-Handler.md]

    # And 用戶 "Alice" 在課程 1 的進度應為 80%

### Output 1（測試程式碼 - tests/test_01_增加影片進度.py）

```python
import pytest
from src.lesson_service import LessonService
from src.lesson_progress_repository import LessonProgressRepository
from src.lesson_progress import LessonProgress

def test_成功增加影片進度():
    # Arrange: 初始化 repository 和 service
    repository = LessonProgressRepository()
    service = LessonService(lesson_progress_repository=repository)

    # Given 用戶 "Alice" 在課程 1 的進度為 70%，狀態為 "進行中"
    # [使用 Aggregate-Given-Handler.md]
    progress = LessonProgress(
        user_id="Alice",
        lesson_id=1,
        progress=70,
        status="IN_PROGRESS"
    )
    repository.save(progress)

    # When 用戶 "Alice" 更新課程 1 的影片進度為 80%
    # [使用 Command-Handler.md]
    service.update_video_progress(user_id="Alice", lesson_id=1, progress=80)

    # Then 操作成功
    # [使用 Success-Failure-Handler.md]
    # （不需要額外程式碼）

    # And 用戶 "Alice" 在課程 1 的進度應為 80%
    # [使用 Aggregate-Then-Handler.md]
    updated_progress = repository.find(user_id="Alice", lesson_id=1)
    assert updated_progress.progress == 80
```

## Critical Rules

### R1: 測試程式碼必須完整
測試邏輯必須完整實作，不能有 `pass` 或空白。

```python
# ✅ 正確：完整的測試邏輯
def test_example():
    repository = ExampleRepository()
    service = ExampleService(repository)
    entity = Example(id=1, name="test")
    repository.save(entity)
    service.do_something(id=1)
    result = repository.find(id=1)
    assert result.name == "expected"

# ❌ 錯誤：測試邏輯不完整
def test_example():
    pass
```

### R2: 介面定義必須完整，但不實作
類別和方法簽名完整，但內部不實作業務邏輯。

```python
# ✅ 正確：定義完整，不實作
class ExampleService:
    def do_something(self, id: int) -> None:
        raise NotImplementedError("紅燈階段：尚未實作")

# ❌ 錯誤：實作了業務邏輯
class ExampleService:
    def do_something(self, id: int) -> None:
        entity = self.repository.find(id)
        entity.process()
        self.repository.save(entity)
```

### R3: 介面必須放在 src/ 目錄
所有業務邏輯相關的類別都放在 src/ 目錄中。

```
✅ 正確結構：
src/
  - lesson_progress.py           # Entity
  - lesson_progress_repository.py  # Repository
  - lesson_service.py            # Service
tests/
  - test_01_增加影片進度.py      # 測試

❌ 錯誤：在 tests/ 中定義業務類別
```

# TDD 重構階段：改善程式碼品質

## 目標

在保持測試通過（綠燈 🟢）的前提下，改善程式碼品質。

---

## 核心原則

### 1. 測試保護原則
每次重構後立即執行測試，確保全部通過。若失敗則立即回滾。

### 2. 小步前進原則
一次只做一個小重構，避免一次改動過多。

### 3. 不強行重構原則
只在真正有改善空間時才重構。程式碼已清晰簡潔時保持原樣，遵循 YAGNI 原則。

### 4. 設計原則遵守
重構時必須遵守 SOLID 設計原則，達到好讀、好維護、好擴充。

### 5. 架構規範遵守
**嚴格遵守** `prompts/rules/程式架構規範.md`，確保分層清晰、職責明確。

### 6. 測試 Warnings 清理
**盡可能清除所有測試 warnings**，保持測試輸出乾淨。warnings 通常指出潛在問題或過時用法。

---

## 重構改善方向

### 1. SOLID 設計原則

#### S - Single Responsibility Principle（單一職責原則）
每個類別/函式只負責一件事。

**範例：**
```python
# ❌ Service 做太多事
class LessonProgressService:
    def update_progress(self, user_id, lesson_id, progress):
        # 驗證權限
        if not self._check_permission(user_id):
            raise PermissionError()
        # 驗證進度
        if progress < 0 or progress > 100:
            raise ValueError()
        # 儲存資料
        self.repository.save(...)
        # 發送通知
        self._send_notification(user_id)

# ✅ 職責分離
class LessonProgressService:
    def __init__(self, progress_repo, permission_validator, notification_service):
        self.progress_repo = progress_repo
        self.permission_validator = permission_validator
        self.notification_service = notification_service

    def update_progress(self, user_id, lesson_id, progress):
        self.permission_validator.validate(user_id)  # 權限驗證交給專門的類別
        lesson_progress = LessonProgress(user_id, lesson_id, progress)
        self.progress_repo.save(lesson_progress)
        self.notification_service.notify(user_id)  # 通知交給專門的服務
```

#### D - Dependency Inversion Principle（依賴反轉原則）
高層模組不應依賴低層模組，兩者都應依賴抽象。

**範例：**
```python
# ✅ Service 透過建構子注入 Repository
class LessonProgressService:
    def __init__(self, lesson_progress_repo, lesson_repo, subscription_repo):
        self.lesson_progress_repo = lesson_progress_repo
        self.lesson_repo = lesson_repo
        self.subscription_repo = subscription_repo

    def get_progress(self, user_id, lesson_id):
        # 業務邏輯使用注入的 repository
        subscription = self.subscription_repo.find_by_user(user_id)
        if not subscription:
            raise SubscriptionNotFoundError()
        # ...
```

### 2. 架構規範遵守

#### 分層架構檢查

**Service (domain services)**：
- ✅ 包含業務邏輯和規則
- ✅ 透過建構子注入 Repository
- ❌ 不直接操作資料庫
- ❌ 不包含 HTTP 處理邏輯

**Repository (data access)**：
- ✅ 封裝資料存取邏輯
- ✅ 在 UT 中使用記憶體內實作
- ❌ 不包含業務邏輯

#### 範例：符合架構規範的重構

**重構前（違反依賴注入）：**
```python
class LessonProgressService:
    def __init__(self):
        # ❌ Service 內部直接建立 Repository
        self.progress_repo = LessonProgressRepository()
        self.subscription_repo = JourneySubscriptionRepository()

    def update_progress(self, user_id, lesson_id, progress):
        # 業務邏輯...
        pass
```

**重構後（符合依賴注入）：**
```python
class LessonProgressService:
    def __init__(self, progress_repo, subscription_repo):
        # ✅ 透過建構子注入 Repository
        self.progress_repo = progress_repo
        self.subscription_repo = subscription_repo

    def update_progress(self, user_id, lesson_id, progress):
        # ✅ 使用注入的 repository
        subscription = self.subscription_repo.find_by_user(user_id)
        if not subscription:
            raise SubscriptionNotFoundError()
        # ...
```

### 3. 程式碼品質改善

#### 消除重複邏輯
```python
# ❌ 重複的訂閱驗證
def update_progress(self, user_id, ...):
    subscription = self.subscription_repo.find_by_user(user_id)
    if not subscription:
        raise SubscriptionNotFoundError()
    # ...

def get_progress(self, user_id, ...):
    subscription = self.subscription_repo.find_by_user(user_id)
    if not subscription:
        raise SubscriptionNotFoundError()
    # ...

# ✅ 提取共用方法
def _validate_subscription(self, user_id):
    subscription = self.subscription_repo.find_by_user(user_id)
    if not subscription:
        raise SubscriptionNotFoundError()
    return subscription

def update_progress(self, user_id, ...):
    subscription = self._validate_subscription(user_id)
    # ...

def get_progress(self, user_id, ...):
    subscription = self._validate_subscription(user_id)
    # ...
```

### 3. 測試 Warnings 清理

#### 目的
清除測試執行時產生的所有 warnings，保持測試輸出乾淨。

#### 常見 Warnings 類型

**1. DeprecationWarning（過時警告）**
```python
# ❌ 使用過時的 API
warnings.warn("This method is deprecated", DeprecationWarning)

# ✅ 改用新的 API
# 根據 warning 訊息更新為推薦的新方法
```

**2. PytestUnraisableExceptionWarning（未捕獲異常）**
```python
# ❌ 資源未正確關閉
def test_example():
    file = open("test.txt")
    # 忘記關閉檔案

# ✅ 使用 context manager
def test_example():
    with open("test.txt") as file:
        # 自動關閉
        pass
```

**3. 記憶體或資源洩漏警告**
```python
# ❌ 物件未正確清理
@pytest.fixture
def setup_service():
    service = MyService()
    yield service
    # 缺少清理

# ✅ 正確清理資源
@pytest.fixture
def setup_service():
    service = MyService()
    yield service
    service.cleanup()  # 確保清理
```

#### 清理步驟

1. **執行測試並檢查 warnings**
```bash
pytest tests/ut/ -v --tb=short
```

2. **針對每個 warning 進行修正**
- 閱讀 warning 訊息
- 找到問題源頭
- 根據建議修正

3. **驗證 warnings 已清除**
```bash
pytest tests/ut/ -v --tb=short  # 應該沒有 warnings
```

4. **確保測試仍然通過** ✅

## UT 重構項目

### 1. Meta 註記清理

#### 刪除的內容
- `# [事件風暴部位: ...]`
- `# [生成參考 Prompt: ...]`

#### 保留的內容
- Given/When/Then/And 業務邏輯描述
- 必要的技術註解（如 "Extract repositories and services"）

#### 範例

**重構前：**
```python
def test_更新影片進度(self, setup_background):
    # Given 用戶 "Alice" 在課程 1 的進度為 50%
    # [事件風暴部位: Aggregate - LessonProgress]
    # [生成參考 Prompt: Aggregate-Given-Handler.md]

    lesson_service = setup_background["lesson_service"]

    # When 用戶 "Alice" 更新課程 1 的進度為 70%
    # [事件風暴部位: Command - update_progress]
    # [生成參考 Prompt: Command-Handler.md]

    lesson_service.update_progress(user_id="Alice", lesson_id=1, progress=70)

    # Then 操作成功
    # [生成參考 Prompt: Success-Failure-Handler.md]
    assert True
```

**重構後：**
```python
def test_更新影片進度(self, setup_background):
    # Given 用戶 "Alice" 在課程 1 的進度為 50%
    lesson_service = setup_background["lesson_service"]

    # When 用戶 "Alice" 更新課程 1 的進度為 70%
    lesson_service.update_progress(user_id="Alice", lesson_id=1, progress=70)

    # Then 操作成功
    assert True
```

### 2. Setup Background Fixture

#### 目的
將重複的依賴初始化代碼提取到 pytest fixture 中，減少重複。

#### 範例

**Setup Background Fixture：**
```python
@pytest.fixture
def setup_background():
    """Background: 測試的共用前置條件"""
    # 初始化 repositories
    lesson_progress_repo = LessonProgressRepository()
    lesson_repo = LessonRepository()
    user_repo = UserRepository()
    subscription_repo = JourneySubscriptionRepository()

    # 初始化 services（透過依賴注入）
    lesson_service = LessonService(
        lesson_progress_repository=lesson_progress_repo,
        lesson_repository=lesson_repo,
        user_repository=user_repo,
        subscription_repository=subscription_repo,
    )

    # Given 系統中有以下用戶
    user_alice = User(name="Alice", level=1, exp=0)
    user_repo.save(user_alice)

    # And 系統中有以下課程
    lesson1 = Lesson(name="物件導向基礎", type="video")
    lesson_repo.save(lesson1)

    # And 用戶 "Alice" 已訂閱旅程 1
    subscription_repo.subscribe("Alice", 1)

    return {
        "lesson_progress_repository": lesson_progress_repo,
        "lesson_service": lesson_service,
        "user_repository": user_repo,
    }
```

**測試方法使用 Fixture：**
```python
def test_更新影片進度(self, setup_background):
    # Extract repositories and services
    lesson_progress_repo = setup_background["lesson_progress_repository"]
    lesson_service = setup_background["lesson_service"]

    # Given 用戶 "Alice" 在課程 1 的進度為 50%
    progress = LessonProgress(user_id="Alice", lesson_id=1, progress=50)
    lesson_progress_repo.save(progress)

    # When 用戶 "Alice" 更新課程 1 的進度為 70%
    lesson_service.update_progress(user_id="Alice", lesson_id=1, progress=70)

    # Then 進度應更新為 70%
    updated = lesson_progress_repo.find_by_user_and_lesson("Alice", 1)
    assert updated.progress == 70
```

## 重構原則總結

✅ **應該做：**
- 清理 Meta 註記
- 保留業務邏輯註解
- 提取依賴到 setup_background fixture
- 遵守 SOLID 設計原則
- 嚴格遵守架構規範（依賴注入、職責分離）
- 清除所有測試 warnings

❌ **不應該做：**
- 將測試特定數據放入 fixture
- 改變測試結構
- 強行簡化可讀性
- Service 內部直接建立 Repository
- 忽略測試 warnings
